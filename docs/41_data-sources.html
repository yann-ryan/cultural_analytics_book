55  Data and Inspiration

On this page you can find links to humanities datasets, suggestions for datasets that would work well for each of the assignments, and examples of projects to get you thinking.

Importing a dataset and dataset standards

For these assignments, you’ll need to begin by importing your dataset as an object into the RStudio/Posit environment. How you do this depends a little on the standard of your dataset. As we’re working with tabular data on this course, your data should in most cases be in one of these formats:

  • Comma separated values (files ending in .csv). A very common tabular data format. Use read_csv() from the Tidyverse package readr (remember to load the package first) to read the file in to Posit.

  • Tab separated values (files ending in .tsv). Another common tabular format. Use read_tsv() from the Tidyverse package readr to read the file.

  • Excel files: Microsoft proprietary format, which can contain multiple sheets. Use read_excel() from the Tidyverse package readxl to read the file.

  • Google sheets. You can read Google sheets directly from the internet using the package googlesheets4.

You can read data originating from either your local machine, or directly from the internet in some cases.

  • If you’re loading from your local machine, remember to upload the file to Posit cloud first, if you’re using it.

  • If you know the path online to a file in one of the formats above, you can simply add the full path as the filename within quotation marks, e.g. read_csv('https://raw.githubusercontent.com/yann-ryan/infovis_data/main/nobel/laureates_df.csv'). For files on GitHub, make sure you use the raw version of the file (click the ‘Raw’ button on the file’s page and copy that address) - the normal GitHub page is a web page, not a csv file.

Whatever dataset you use, a really important task is to read the documentation available, so you understand, as best as possible, how it was made and who was responsible for it. If you can’t find out where a dataset came from, don’t use it.

Warning

If you do want to use your own dataset, be aware that your account on Posit Cloud has a limit of 1GB of RAM. This means that you will not be able to load larger datasets into memory, and you’ll get an error. In this case, it’s best to install R and RStudio on your own machine, which likely has more RAM. Datasets below which are likely to be too big for Posit Cloud are marked (large).

Datasets used on the course

The datasets we’ve worked with in class are relatively clean and simple, by humanities data standards. For Assignment 1 especially, I highly recommend using one of these: data cleaning and figuring out formats can be very time consuming, so unless you are very comfortable with these things, think carefully before choosing a bespoke dataset.

  • The Titanic dataset. There are many versions of this on the internet, because it is widely used in machine learning problems. I created a version based on this dataset, because it contains the full list and hasn’t been divided into different parts for training and testing machine learning algorithms. There is a little information on how the dataset was constructed, but unfortunately the link to further information is no longer working. My version is available here.

  • The Bellevue Almshouse data. Records of immigrants who were admitted to the Bellevue Almshouse (house for the poor) in New York in the 1840s. You can find more information and links to the data here.

  • The Movie Dialogue dataset. You can find more information about this dataset here. I created the third file, imdb_genre, from a larger IMDB dataset. You can find that file here.

  • The Nobel Prize Winners dataset. Two tables, with information on the Nobel Prizes and the Nobel Prize winners. I created this using the official Nobel API. You can find the files here.

Suggested datasets

If you’d like to try something different, the datasets below are similar in spirit to the ones we’ve used in class: tabular, reasonably clean, documented, and about culture or history. Each comes with an idea of the kind of question you could ask of it, but these are just starting points.

When choosing, keep to something broadly humanities-related (so not primarily natural sciences or economics), and check before you commit that there is documentation telling you where the data came from and how it was made - you’ll need it to write a good report.

Good for a first visualisation (Assignment 1)

  • Art history textbooks (TidyTuesday). Every artist who appears in the two most widely used art history survey textbooks (Janson’s and Gardner’s) across all their editions, with the artists’ gender, ethnicity, nationality, and how much page space each one received. A very direct way into questions about the canon: who gets included, and how has that changed over time? Comes from the R package arthistory.

  • Eurovision (TidyTuesday). Results of every Eurovision Song Contest, plus the votes cast between countries. Good for rankings over time, and the voting table invites questions about ‘bloc voting’ and which countries favour which (there’s even a mapping project hiding in there).

  • Bob Ross paintings (TidyTuesday). Every painting from the TV show The Joy of Painting, with the colours used in each one, by season and episode. Small, friendly, and nice for experimenting with colour scales - you can use the actual hex codes of the paints.

  • Billboard Hot 100 (TidyTuesday). Weekly positions of every song on the US Billboard chart since 1958, joined to Spotify’s audio features (danceability, tempo, and so on). Has songs got shorter, sadder, or faster? A good chance to practise dates and joins.

  • The Tate collection. Metadata for around 70,000 artworks and 3,500 artists in the Tate’s collection: titles, dates, media, dimensions, acquisition year, and artists’ birth and death places. It’s a 2014 snapshot and no longer updated (which is worth mentioning in your report!), but it is clean and well structured.

  • The Museum of Modern Art collection. Similar to the Tate data but bigger and regularly updated: artworks with dates, departments, dimensions and acquisition dates, plus artists’ nationality, gender and birth/death years. FiveThirtyEight’s guide to MoMA’s paintings gives a sense of what’s possible.

  • Post45 Data Collective. Peer-reviewed datasets about twentieth- and twenty-first-century literature, each with a short essay explaining how it was made. Good choices are the New York Times hardcover fiction bestsellers (1931-2020), the index of major literary prizes in the US, and the British literary prizes dataset. Questions about gender, genre and prestige come out of these very naturally.

  • Project Gutenberg metadata, via the R package gutenbergr. Metadata (not text) for the tens of thousands of books on Project Gutenberg: title, author, authors’ birth and death years, language and subject headings, loaded with gutenberg_metadata, gutenberg_authors and gutenberg_subjects. What does the ‘public domain canon’ look like?

Good for a map (Assignment 2)

  • Shakespeare and Company Project. Records from Sylvia Beach’s lending library in interwar Paris, with geocoded addresses for its members. An article describes the data, which is divided into members, books, and events (mostly library loans). Map where readers lived, or join the tables to see who borrowed what.

  • Rijksmonumentenregister. The Dutch register of national monuments - around 60,000 protected buildings and sites, with their type, building period and location. A good local option: map monuments by type or era in Leiden or your home town. Bulk downloads are available via data.overheid.nl (search for ‘rijksmonumenten’).

  • Dutch-Asiatic Shipping (Huygens Institute). Around 8,000 voyages made by VOC ships between the Netherlands and Asia, 1595-1795, with ships, dates, ports of departure and arrival, and crew numbers. Good for maps of routes and for time series.

  • Pantheon. Tens of thousands of ‘famous’ historical people, with birthplaces (including coordinates), occupations and a measure of how much their Wikipedia pages are viewed. Fun to map, but also an excellent dataset to be critical about: what does ‘famous’ mean, and whose fame does Wikipedia record?

  • A cross-verified database of notable people (Laouenan et al., 2022) (large). Around 2.3 million notable people from 3500 BC to 2018, assembled from Wikipedia and Wikidata, with birth and death dates and places, gender and occupation. Much bigger and more systematic than Pantheon; filter it down to a period or region that interests you.

  • Pleiades. A gazetteer of tens of thousands of places in the ancient world, with coordinates, place types and the periods in which they were in use. Download the CSV ‘dumps’. Good for anyone interested in classics or archaeology.

  • Mapping Inequality. Digitised versions of the 1930s US government ‘redlining’ maps, which graded neighbourhoods by supposed mortgage risk, largely along racial lines. Downloadable as GeoJSON, so you can practise with polygons rather than points.

  • The World Atlas of Language Structures, based on WALS. Linguistic features of the world’s languages, with coordinates. It’s a little difficult to find what you need, but the languages table is the most important. Pair it with this dataset of endangered and extinct languages.

More ambitious

These are bigger, messier, or need more care, but reward the effort if you’re feeling confident.

  • SlaveVoyages. The Trans-Atlantic and Intra-American slave trade databases: records of around 36,000 voyages, with ports, dates, and numbers of enslaved people embarked and disembarked. One of the most important datasets in digital history, and one which demands careful thought about how to visualise human suffering - read the Vane and Pearce reading on sensitive topics before using it.

  • The Metropolitan Museum of Art Open Access (large). Around half a million objects from the Met’s collection in one CSV, covering everything from ancient Egypt to modern design. Lots of missing values and inconsistencies, which is realistic and makes for good discussion in a report.

  • Old Bailey Online and the Digital Panopticon. Nearly 200,000 criminal trials at London’s central criminal court, 1674-1913, and the later lives of convicts. Getting tabular data out takes some work; Sharon Howard’s blog posts show how, with R and tidyverse code.

  • British Library newspapers title list. Every newspaper title held by the British Library, with places and dates of publication. Good for mapping the growth of the press.

  • litRiddle. Data from a large Dutch reader survey about contemporary novels, combined with information about the books and authors. There’s also an R package: install.packages("litRiddle").

  • IMDb non-commercial datasets (large). Every film and TV title on IMDb, with genres, runtimes, ratings and cast and crew.

  • HathiTrust Hathifiles (large). Catalogue metadata (not content) for the millions of volumes digitised by HathiTrust. Look for the most recent file starting with hathi_full.

Data repositories and lists

There are many, many sources of datasets available online. Look for relatively simple csv and tsv files or sets of files, and avoid those that mention APIs or Linked Open Data unless you are comfortable working with these things.

National and international statistics

  • CBS Statline: Dutch statistics. Also an R package, cbsodataR.

  • Eurostat: official EU statistics, at different regional levels - including cultural statistics such as cultural employment and participation.

  • e-Stat: official statistics repository of Japan. The statistics dashboard is particularly useful.

Humanities repositories

  • Journal of Open Humanities Data. Short articles describing humanities datasets, with the data attached and possible use cases. A great place to find well-documented data.

  • Post45 Data Collective (see above).

  • TidyTuesday. A weekly data challenge with a large archive of datasets, organised by year and week. Many aren’t relevant to the humanities, but those that are tend to be clean and documented.

  • DANS Social Sciences and Humanities: the Dutch national repository. Lots of datasets, but they can be very specific and not always easy to use.

  • KB Labs datasets from the Dutch national library (many are text-based but some are structured).

  • The Pudding has some nice and often fun datasets, though they have a very American focus.

  • Melanie Walsh’s Introduction to Cultural Analytics has a page of datasets. Not all are tabular - some are primarily text, which is outside the scope of this course.

  • The Google dataset search. However, make sure you can trace back the provenance!

  • The ‘DH toychest’ datasets and this list of museum APIs. Both are old, so expect some broken links, but there are still useful things there.

Tip

For very large datasets, it may also be helpful to use an R package such as data.table which is more efficient than Tidyverse for working with very large data. data.table has a very different syntax to the Tidyverse, but there is a package, tidytable, which converts between the two.

R packages

There are many R ‘dataset packages’. These can be very useful, because accessing the data is simple - you just need to install a package and then follow some instructions to load the dataset, rather than find and upload a spreadsheet file. They are also generally formatted so they are easy to use in R.

  • HistData: classic datasets from the history of data visualisation - including Florence Nightingale’s data on causes of death in the Crimean War, John Snow’s cholera map, and Minard’s data on Napoleon’s march on Moscow. You could recreate (and improve on?) a famous chart.

  • arthistory: the art history textbook data described above.

  • gutenbergr: Project Gutenberg metadata (see above).

  • taylor: the complete discography of Taylor Swift, with Spotify audio features and lyrics. See the package website.

  • refugees: UNHCR data on refugees and displaced people, from 1951 onwards.

  • A huge list of datasets in R packages here - but again, try to only use those with good documentation.

R packages which connect to an API

  • The osmdata package. Download geographic data from OpenStreetMap through R. Very fun to work with, though takes some understanding of the queries. Try a tutorial here if you’re interested.

  • spotifyr allows you to download data from Spotify. You need to register for an API key. Be aware that since late 2024 Spotify no longer gives new apps access to its ‘audio features’ (danceability, energy and so on), so much of what you’ll see in older tutorials won’t work. Datasets which already include these features, such as the Billboard data above, are a better bet.

Social media data

Unfortunately, doing analysis on social media data has become very difficult in the last few years as companies have locked down their services. Twitter/X ended free and academic access to its API in 2023, which means older collections of tweet IDs can no longer be ‘hydrated’ into actual tweets, and Reddit has also heavily restricted access. Unless you have a ready-made, documented dataset (and permission to use it), I’d avoid social media data for this course.

Inspiration for your reports

  • Current Research in Digital History (short historical essays with graphics).

  • Journal of Digital History (digital history articles with a code layer).

  • Journal of Cultural Analytics (computational articles on culture, often with visual elements).

  • The Pudding (data journalism visual essays with interactive elements).

  • Visualizing Emancipation (a nice example of a visual essay aimed at an academic readership).

  • The Killing Times (example of an interactive visual essay, for those interested in using Shiny).

  • Short visual essays by FiveThirtyEight such as this one, and their guide to MoMA’s paintings, which is a nice example of the kind of project you could make with collections data.

  • Sharon Howard’s data blogs. Some use other tech, but many are straightforward R/tidyverse visualisations with historical data, such as here.

  • The Programming Historian (peer-reviewed tutorials, several of which use R and historical data).

  • Cool stuff made with cultural heritage APIs.
